TurboFEMM Changelog
===================

Version 4.3.2 (2026-03-19)
---------------------------

NEW FEATURES:
  - Az-based eddy current loss model for solid low-mu conductors (magnets)
    with per-block mean subtraction to cancel gauge/motion artifacts
  - Rotor-frame solid loss computation: rotates sampled B into the local
    co-rotating radial/tangential frame before dB/dt calculation, removing
    spurious losses from the main synchronous PM field
  - Label-aware B-history lookup for iron loss: each snapshot now stores
    block label indices for more accurate material-region matching
  - Rotor-frame backiron probe values exportable in motion CSV for
    debugging local field continuity

IMPROVEMENTS:
  - Density Plot menu: mutually-exclusive radio selection, hide/disable
    unsupported entries (|J| removed, |Re(B)|/|Im(B)| hidden for DC,
    Iron Loss disabled when no loss data)
  - Retina/device-pixel resolution rendering for offscreen PNG/GIF capture
  - Iron loss heatmaps now use smoothed nodal shading instead of hard
    per-triangle boundaries
  - |H| density overlay rendering fixed (was showing zero everywhere)
  - Mesh reusability validation before Analyze to prevent crashes from
    stale motion sweep state

BUG FIXES:
  - Fixed Analyze-after-motion crashes caused by reusing invalid in-memory
    mesh state
  - Fixed motion GIF/PNG capture inheriting the live GUI density selection
    and producing blank/non-field frames
  - Fixed duplicate iron-loss stills being written into motion PNG output
  - Fixed offscreen GIF quantization artifacts by using per-frame local
    palettes instead of one coarse global palette
  - Removed sliding band feature (was not working reliably) and cleaned
    up associated UI controls and .fem file metadata

Version 4.3.1 (2026-03-17)
---------------------------

IMPROVEMENTS:
  - Motion PNG/GIF capture now always renders `|B|` with a fixed capture
    scale, so animations stay visually consistent across sweep steps
  - PNG/GIF export now renders at Retina/device-pixel resolution for
    smoother anti-aliased captures
  - Iron loss heatmaps now use smoothed nodal shading instead of hard
    per-triangle boundaries
  - Added optional "accurate solid rotor losses" mode for motion sweeps
  - Motion CSV can now include signed rotor-frame backiron probe values
    for debugging local field continuity

BUG FIXES:
  - Fixed motion GIF/PNG capture inheriting the live GUI density selection
    and producing blank/non-field frames
  - Fixed duplicate iron-loss stills being written into motion PNG output
  - Fixed Analyze-after-motion crashes caused by reusing invalid in-memory
    mesh state
  - Fixed several Density Plot menu issues: mutually-exclusive selection,
    broken `|H|` rendering, and misleading/unsupported entries
  - Fixed motion capture/export rendering to include the full geometry
    consistently
  - Fixed offscreen GIF quantization artifacts by using per-frame local
    palettes instead of one coarse global palette
  - Removed stale sliding-band controls/guide artifacts from the normal GUI
    workflow while the feature remains disabled

Version 4.3.0 (2026-03-13)
---------------------------

NEW FEATURES:
  - 3-phase motor module: automatic commutation, phase angle optimizer,
    RMS current input, ABC circuit assignment, pole pair configuration
  - Iron loss computation: Steinmetz model (Kh, Kc, Ke) with material
    presets (M-19, M-36, M-43, etc.)
  - Eddy current losses for solid conductors (Az-based, e.g. NdFeB magnets)
  - Parametric motion sweep: rotate or translate a group with per-step
    results (PNG frames, animated GIF, CSV export)
  - Density heatmap overlay with manual color scale controls (min/max)
  - H-adaptive mesh refinement (ZZ error estimator, two-phase refine/coarsen)
  - Metal GPU-accelerated PCG solver backend (macOS)
  - In-process solver (no disk I/O for intermediate results)
  - Comprehensive UI tooltips on all dialog parameters

IMPROVEMENTS:
  - Torque diagnostic output on first motor sweep step (depth, lengthConv,
    maxB, group, rotation center) for debugging scaling issues
  - Torque scaling test verifying 1A/5A/10A consistency
  - Results overlay persists across motion sweep steps
  - CSV export with configurable column selection
  - Iron loss results in CSV (total watts, per-region breakdown)
  - Motor config dump in sweep log for diagnostics
  - Per-step diagnostic logging (electrical angle, phase currents,
    energy, MST torque)

BUG FIXES:
  - Fixed GPU PCG solver divergence on fine meshes (>80k nodes): automatic
    fallback to CPU double-precision PCG when float32 GPU solver produces
    NaN or stalls
  - Unified "Analyze" button to use in-process solver (same as motion sweep),
    eliminating external fkn process and disk I/O
  - Fixed motor optimizer finding braking angle instead of motoring angle
    (peak detection now requires positive torque)
  - Fixed commutation tracking sign (subtract rotor advance, not add)
  - Fixed CSV column header/data ordering mismatch for motor columns
  - Fixed depth units in torque and energy computation (was 1000x off
    for millimeter models)
  - Fixed depth units in iron loss total watts computation
  - Fixed iron loss W/m^3 vs W/kg confusion (Steinmetz coefficients
    are in W/m^3, not W/kg)
  - Fixed optimizer VW torque sign to match physical MST torque direction
  - Removed auto-mesh/solve on file open (was blocking UI for large models)
  - Fixed overlay disappearing after motion sweep
  - Fixed 3-phase commutation sign convention

ARCHITECTURE:
  - GPU backend abstracted behind GPUBackend interface
  - Anderson acceleration for nonlinear materials with relaxation fallback
  - Triangle library for mesh generation (PSLG mode)
  - Full compatibility with original FEMM 4.2 .fem file format
  - Qt 6 GUI with cross-platform support

Based on FEMM 4.2 by David Meeker (21 Apr 2019).
